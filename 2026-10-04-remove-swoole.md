## Goal

Remove the `swoole` extension dependency from Winter Boot while keeping all public framework behavior (DI, REST, DB, caching, async/scheduling APIs, KV/queue, sessions) working on PHP core only (PHP 8.6 baseline), using an embedded PHP-core HTTP server (Tomcat-style: the framework itself serves HTTP, no external web server, no FPM) and PHP-native concurrency (Fibers + plain processes + streams) instead of Swoole coroutines/servers/channels.

## Success Criteria

- `composer.json`/`composer.lock`, `build/docker/Dockerfile`, and docs no longer require `ext-swoole`; a single `php app.php` process boots and serves HTTP with no nginx/Apache/FPM in the path.
- Full unit suite green without Swoole: `php srcTests/run.php`.
- No `Swoole\`, `Co\`, `go()`, `chan`/`Channel`, `SWOOLE_*` references remain in `src/` (checked by grep).
- PDBC works per-request with no cross-request connection leakage; concurrent requests never share a connection handle.
- Async (`#[Async]`) and scheduling (`#[Scheduled]`, `DaemonThread`) have a documented PHP-core execution model (embedded-loop-safe) with no `Co::sleep` or Swoole Http Client.
- Release scope: all work lands on the new `3.0.0` release branch (major version: Swoole removal, PHP 8.6 baseline, embedded server); `2.x` stays Swoole-based with no backports.

## Approach

Embedded-server, share-nothing per request; Fibers only for in-request structure, never for parallelism. Key decisions:

- **HTTP runtime: embedded PHP-core server, no external web server.** Like embedded Tomcat in Spring Boot, the framework itself opens the listening socket (`stream_socket_server`), multiplexes connections with the PHP 8.6 polling API, and runs each request through the existing `DispatcherServlet` with fresh per-request objects — a single `php app.php` process serves traffic, no nginx/Apache, no FPM, no extension. Stateless services (DI container) are built once per worker at start; all request state is per-request and discarded after the response, which is what removes the Swoole-era cross-request contamination class. HTTP scaling is pre-fork workers: the master binds the listening socket and forks N HTTP workers (configured count); each worker runs its own poll loop + Fibers with its own container and connections while the kernel balances accepts. The master only supervises (reaps/re-forks dead workers, graceful reload via signals) — it never serves traffic. Rejected: FPM (speaks only FastCGI, so it needs a front you ruled out), third-party long-lived servers (FrankenPHP/RoadRunner — a dependency plus the same shared-state class), `php -S` (dev-only, single-threaded). Owned HTTP hardening (timeouts, keep-alive/connection limits, slow-client protection) becomes framework code and is validated explicitly in Step 2.
- **Concurrency model: synchronous per-request code + Fibers for cooperative structure + OS processes for background work.** PHP Fibers are cooperative single-threaded suspend/resume (no parallelism; a blocking syscall still blocks the OS thread), and Generators are iterators, not concurrency — so neither replaces Swoole channels/timers for I/O overlap. Real overlap comes from non-blocking streams multiplexed by the new polling API; real background work comes from separate processes supervised externally (systemd/supervisor/cron), not Swoole workers.
- **DB: drop coroutine-scoped pools; use per-request connections (+ PDO persistent where valid).** The `PdoDataSource`/`OciDataSource` + `CoroutineScopedPool` design (Channel + `Coroutine::getCid` + `Coroutine::defer` release hooks) exists only because one Swoole worker multiplexes many requests; in the embedded server one request owns its connection and releases it at request end (aided by existing `php-ext` `deferred()`). Rejected: Fiber-scoped pools as default — keeps the cid-recycling/leak cleanup burden for no benefit; keep a tiny optional Fiber-local cache only if a single request fans out Fibers onto one connection with explicit non-sharing rules.
- **KV/queue/transports: replace `Swoole\Server`/`Swoole\Client` daemons with PHP-core transports.** `KvServer`/`QueueServer` (Swoole TCP servers + `Swoole\Process` workers) and `KvClient`/`QueueClient` (`Swoole\Client(SWOOLE_SOCK_TCP|SWOOLE_KEEP)`) become either (a) plain `stream_socket_*` TCP with the PHP 8.6 polling API for multiplexing, or (b) backed by existing module backends (Redis) — decision per component in Step 4. `OpenSearchHttpClient`'s `Swoole\Coroutine\Http\Client` path becomes ext-curl/plain streams.
- **Timers/sleeps/processes: replace with core equivalents.** `Swoole\Timer::tick/after/clear` (`IdleCheckRegistry`, `KvServerProcess`), `Co\System::sleep` (`ScheduleWorkerProcess`, `AsyncWorkerProcess`), `Swoole\Process` + `SWOOLE_HOOK_ALL` + `ServerWorkerProcess`/`AttachableProcess`/`MonitoringServerProcess`, and `WinterServerAdmin`/`ServerPidManager` move onto the embedded loop (poll timeout drives timers) for in-process needs, or to pcntl/supervised CLI workers for background jobs; sub-minute precision stays in-process, cron-grade scheduling stays external.
- **Shared memory: replace `Swoole\Table`/`Swoole\Atomic`.** `ShmTable` (wrapping `Swoole\Table` incl. `TYPE_INT/STRING/FLOAT`) and `WinterTable` (`Swoole\Atomic` counter) lose their backend without the ext; replace with APCu / file / Redis / DB depending on scope (request vs host-local vs distributed) — decided per use-site in Step 4.
- **`php-ext/winter_boot`: extend with bundled third-party C libraries for server hot paths.** The ext stays a single self-contained `.so` (static linking, no new runtime shared-lib deps, MIT-compatible licenses only — no GPL) and keeps `deferred()` semantics untouched. Candidate natives: event-poll wait and HTTP/1.1 request parsing behind a small PHP API; all framework logic (routing, dispatch, request state) stays in PHP. Hard rule: every native path has a pure-PHP fallback (poll API, PHP parser) so the framework always runs without the ext (tests, dev machines). Step 2 picks the exact native surface after the benchmark gate shows where PHP-level cost actually is — no C code before measurement.

## Steps

1. **Freeze the Swoole inventory (no code changes).** Confirm the full surface with grep and record per-file disposition: `src/core/app/WinterWebSwooleApplication.php` (bootstrap + `Swoole\HTTP\Server` + worker/manager/task callbacks + async/sched/KV/queue process wiring), `src/core/context/WinterServer.php` (`Swoole\Server`, `Server\Port`, event callbacks, pid/admin), `src/core/context/WinterTable.php` (`Swoole\Atomic`), `src/io/shm/ShmTable.php` (`Swoole\Table`), `src/core/web/SwooleDispatcherServlet.php` + `src/web/http/SwooleRequest.php` + `src/web/http/SwooleResponseEntity.php` + `src/io/stream/SwooleOutputStream.php` (HTTP adapter), `src/coroutine/` (`SwooleCoroutineScopeProvider`, `CoroutineRunner` incl. `Coroutine::create`/`run`, `CoroutineScopedPool` Channel logic, `NullCoroutineScopeProvider` as the request-scope reference), `src/pdbc/pdo/` + `src/pdbc/oci/` (`Channel`, `getCid`, `defer` pools), `src/io/timer/IdleCheckRegistry.php` (`Timer::tick/clear`), `src/io/process/*` (`Swoole\Process`, `Co\System::sleep`, hook flags), `src/io/kv/` + `src/io/queue/` (Swoole TCP server/client), `src/migrations/OpenSearchHttpClient.php` (`Swoole\Coroutine\Http\Client`), `src/util/async/AsyncInMemoryQueue.php`, `src/task/async/stereotype/Async.php` + `src/task/scheduling/stereotype/Scheduled.php` + `EnableAsync/EnableScheduling`, `src/io/server/WinterServerAdmin.php` + `ServerPidManager.php`, `src/web/session/RequestSession.php` (keep shape; drop Swoole-specific comments), `srcTests/swoole/*` + `SwooleRequestTest.php`/`CurrentHttp*Test.php` usages, `build/docker/Dockerfile` (`pecl install swoole-6.2.2`), `composer.json` (`swoole/ide-helper`). Validation: inventory list committed; `php srcTests/run.php` baseline recorded with and without Swoole loaded.
2. **Build the embedded server alongside Swoole (default off).** New `WinterWebApplication` path with a master process that binds `stream_socket_server` and pre-forks N HTTP workers (configured count, replacing `worker_num` semantics); each worker runs the accept/poll loop (poll API) with per-connection Fibers and per-request fresh `HttpRequest` + `DispatcherServlet` dispatch (no `$_SERVER` reads inside handlers; keep the existing "never read superglobals in handler code" rule), plus owned hardening: read/write timeouts, keep-alive and connection-count limits, slow-client protection, sanitised access/error logging (no raw bodies/headers). DB handles and ext/poll resources are created after fork, never inherited. Keep `WinterWebSwooleApplication` untouched this step so both runtimes run the same Dispatcher + test suite. Prototype pure-PHP first; ext natives are added only for hot paths the benchmark gate identifies. Validation: hello-controller served by plain `php app.php` (including a slow-client/timeout probe); worker smoke with N=2 (kill -9 a worker, master reforks, traffic continues); Swoole path still green.
3. **De-coroutinize request scope and PDBC.** Make `NullCoroutineScopeProvider` semantics the default (one scope = one request); add explicit Fiber-local scope only if needed. Replace `CoroutineScopedPool`/cid-keyed pools with per-request connection ownership + `deferred()` cleanup; keep pool class only as a deprecated shim or delete. Handles are created after fork and never shared across workers. Pooling becomes per-worker and process-local (no cid keying, no Channels): `connection.maxConnections` turns into the per-worker cap with DB-side sizing `workers × maxConnections ≤ db max_connections`; `connection.idleTimeout` + `validationQuery` are retained for reaping and checkout ping; `connection.persistent` (PDO persistent) stays as the zero-code reuse option with mandatory checkout reset/validation (no leaked transactions, session vars, or temp tables). One in-flight Fiber per handle — a worker overlapping DB-using Fibers holds more than one handle, each checked out exclusively. Prove no sharing: concurrent requests against the embedded server (ab/hey or two curls with artificial delay) never observe each other's transactions/session rows. Validation: PDBC + transaction tests against the embedded server; race repro from the Swoole era (two concurrent requests, one sleeping in-txn) passes.
4. **Migrate each Swoole subsystem behind the same interfaces.** One sub-slice each, in this order: (a) HTTP adapter (retire `SwooleRequest`/`SwooleResponseEntity`/`SwooleOutputStream`/`SwooleDispatcherServlet` once the embedded adapter is stable); (b) timers + workers (`IdleCheckRegistry`, async/sched executors, `DaemonThread`, `MonitoringServerProcess`) to pcntl/supervised CLI workers; (c) KV/queue server+client to streams/poll or Redis backend; (d) `ShmTable`/`WinterTable` to APCu/file/Redis/DB per scope; (e) `OpenSearchHttpClient` to curl/streams; (f) `WinterServerAdmin`/`ServerPidManager`/pid files to supervision-native health/reload. Validation per slice: focused `srcTests/*Test.php` + a live smoke (KV put/get, queue enqueue/dequeue, scheduled task fires, OpenSearch query).
5. **Delete Swoole and cut over.** Remove `ext-swoole`/ide-helper from `composer.json`, require `php >= 8.6`, ship a single `php:8.6-cli-alpine` image that runs the embedded server on the app port (no fpm/nginx processes), update docs; delete Swoole-only classes/shims; move `srcTests/swoole/` to archive or rewrite as embedded-server/Fiber tests; update ` WinterBootApplication` docs to the embedded starter. Then per repo rules: `php -l` every edited file, `php srcTests/run.php` green, docs sync in `wb-mdx` (`reference/application-yml.mdx` for any changed `server:`/`winter.task.*` keys + concept pages) verified with `./build.sh`, `CHANGELOG.md` entry, `VERSION.txt` bumped to `3.0.0` on the branch per the release checklist. Validation: fresh checkout of the `3.0.0` branch with no Swoole installed passes suite and serves the example app.

## Validation Plan

- Inventory: `grep -rni "swoole\|Swoole\\\\\\|Co\\\\\\|Coroutine::\\|go(" src/ php-ext/ srcTests/ build/ --include="*.php" -l` returns empty for `src/` (post-migration); pre-migration output is the Step 1 list.
- Suite: `php srcTests/run.php` green on a machine without `ext-swoole`; `php -l <file>` on every edited file.
- Concurrency proofs: (1) two concurrent requests with overlapping transactions show isolation; (2) KV/queue smoke under parallel clients; (3) scheduled/async jobs fire without Swoole; (4) OpenSearch migration path works over curl/streams; (5) slow-client/timeout probe against the embedded server.
- Highest-risk check: the PDBC isolation test (Step 3) — it is the reported production failure class (per-Swoole-context connections, race conditions) and must pass before any cutover.
- Benchmark gate (before cutover): same app, same machine, `wrk`/`hey` at fixed concurrency — record RPS, p50/p99 latency, and process memory on the Swoole build, then on the embedded-server prototype (Steps 2–3). Step 5 proceeds only with measured numbers, not estimates.

## Risks / Open Questions

- **Poll API exact userspace shape (conditional).** The poll RFC motivation inspected here covers an internal polling API plus a minimal userspace `stream_select()` replacement for AMPHP/ReactPHP/Revolt-style backends (not a full event loop), with FPM-worker event handling and timers as internal consumers. The exact PHP 8.6 function/class names were not fully visible in the fetched excerpt — confirm from the RFC body before writing transport code; until then keep new TCP code on plain blocking streams + short timeouts.
- **`stream_errors` adoption (conditional).** Inspected: `error_mode` (`Error`/`Exception`/`Silent`), `error_store` (`Auto`/`None`/terminating/non-terminating/`All`), `error_handler` callback, `stream_last_errors()` — useful for the new stream/curl transports (silent + structured errors instead of warnings). Decide per transport in Step 4.
- **Throughput/latency and memory cost vs Swoole (unmeasured — see benchmark gate).** Cost sources: (a) bootstrap — Swoole boots once per worker and amortizes DI/reflection across requests; the embedded server likewise builds the stateless container once at start (request state stays per-request), with OPcache + `opcache.preloading` covering class loading; (b) PHP-level I/O multiplexing + HTTP parsing per connection — the reason the ext may grow C hot paths (see native-acceleration decision), decided by measurement, never up front; (c) connections — per-request DB ownership instead of a shared coroutine pool (persistent PDO helps). CPU scale comes from pre-fork HTTP workers (count tuned by the benchmark gate, alongside the ext-native decision). Load-test before cutover; keep rollback = previous release tag + Swoole image.
- **Sub-minute scheduling and Prometheus push.** Cron granularity and multi-process metric aggregation need explicit owners in Step 4; `winter.task.*` yml keys may change (docs sync mandatory).
- Assumptions: PHP 8.6 runtime baseline (embedded loop uses the poll API, no `stream_select` fallback); no new PECL/runtime PHP dependency; `php-ext` may bundle MIT-compatible C libs (statically linked, single `.so`) but never Swoole code.
